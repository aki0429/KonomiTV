## 起動時設定検証と録画監視の方式

単独運転の main を `LoadValidated` へ接続した。本家と同じく全項目の既定値を先にマージし、URL・エンコーダー・ポートも起動時に確認する。
検証に失敗すると DB を開かず、起動ログにも理由を残す。型と保存先はプロキシ併走モードでも検査するが、併走中の Python と競合するポート等の実機検査は省く。
旧 Go 固有の IPTV は明示した起動互換モードだけで読み、設定 API の backend 選択肢は本家のままとした。

本家の `LoadConfig` 本体を、lock と同じ ruamel.yaml 0.18.12・Python 3.13・Pydantic 2.14.3 で実行し、117 件を照合した。
YAML の型、アンカー/マージ、Docker の順序付きパス変換、バイパス時も残る型検査、既定値の実機確認を含む。
machine int を超える YAML 整数を丸めず保持し、実行用の数値へ変換しても GET は元の検証済み整数を返す。
CLI の子プロセス試験でも、不正な型やエンコーダーの欠落で DB 作成前に停止し、理由をログへ保存することを確認した。

録画監視は Linux のネットワーク FS を巡回へ回し、通常保存先は変更通知を使う。
同じマウントポイントの最後のエントリー、最も深いマウント、ネットワークの子マウント、シンボリックリンクを扱う。
本家の分類関数と watchfiles 1.3.0 の実ヘルパーを実行した 47 件で、環境変数の有効/無効、WSL、Unicode の十進数字、分からミリ秒への丸めを照合した。
重なった保存先の担当を整理し、巡回する親ルートから通常監視の子ルートを除外する。

通知は 50ms 単位でまとめ、追加・変更されたファイルと新しいサブフォルダだけを観測する。通知が使えない場合は設定した間隔で再列挙する。
全保存先で共通の 5 秒時計を使い、録画中のファイルだけを stat して完了を検出する。重い解析や全件巡回とは独立させた。
変更通知では追跡サイズを更新するが、解析が参照している構造体を変更しない。削除・移動・空の保存先の保護も保持した。
強制巡回で早期に登録されないこと、次の巡回を待たず完了すること、新しいサブフォルダとリンク経由の保存先を検証した。
